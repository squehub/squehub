# Published v1.x docs compared with the v2 working tree

The [published v1.x index](https://squehub.com/docs/v1.x) covers installation, configuration, routes, controllers, views, models, middleware, migrations, Dumper, helpers, tasks, notifications, Mail, and packages. Those pages describe v1.x and must remain available. This audit identifies where a separate `/docs/v2.x` set needs different examples and where current v2 systems need their own pages. It is a comparison of published text with the current v2 source, not a claim that v2 is released.

| Topic | Published v1.x example or convention | Current v2 documentation and code |
| --- | --- | --- |
| Installation | [v1.x installation](https://squehub.com/docs/v1.x) shows Composer `create-project`, `.env.example`, and a fixed `localhost:8000` URL. | [v2 Installation](Installation.md) uses `.example.env`, generated `APP_KEY`, Doctor, and the available-port development server. Composer still publishes the older generation. |
| Routing | [v1.x routing](https://squehub.com/docs/v1.x/routing) leads with `$router->add(...)` and `Controller@method`. | [v2 Routing](Routing.md) leads with `Route::path(...)->get(...)`, names, groups, resources, and route middleware. The old registration remains a compatibility bridge. |
| Views | [v1.x views](https://squehub.com/docs/v1.x/views-and-blade) includes root `/views/` and examples of layouts, includes, and notification flash directives. | [v2 Views](Views.md) uses `Project/Views`, published and bundled package views; root views are no longer searched. It documents escaped `{{ }}`, raw `{!! !!}`, sections/layouts, forms, and the separate legacy flash directives. |
| CLI | [v1.x CLI](https://squehub.com/docs/v1.x/cli) says `make:*` commands scaffold files. | [v2 CLI](Cli.md) and [Generators](Generators.md) document five working generators, including modern `make:seeder`; Doctor, Queue, Scheduler, route listing, migrations, Seeders, and packages have separate contracts. V1 Dumper commands are retired in v2. |
| Packages | [v1.x packages](https://squehub.com/docs/v1.x/packages) describes a required package-named entry file and lowercase package path. | [v2 Packages](Packages.md) documents the actual capitalized package path, route/view/scheduler loading, Git clone installer, and lack of universal provider discovery. |
| Data and models | The v1.x navigation groups models, migrations, and Dumper. | v2 separates [Database](Database.md), [Schema](Schema.md), [Migrations](Migrations.md), [Models](Models.md), [Relationships](Relationships.md), [Scopes](Scopes.md), [Soft deletes](SoftDeletes.md), [Collections](Collections.md), [Pagination](Pagination.md), [Seeders](Seeders.md), and [Factories](Factories.md), because their contracts differ. |
| Notifications and Mail | The v1.x navigation has notification and mail pages. | v2 distinguishes browser flash messages from [deliverable Notifications](Notifications.md), and documents [Mail](Mail.md), Queue integration, retries, and diagnostics explicitly. |

The v1.x sidebar does not provide dedicated pages for several implemented v2 pillars: [HTTP Request/Response](Http.md), [Validation](Validation.md), [Sessions](Sessions.md), [CSRF](Csrf.md), [Authentication](Authentication.md), [Authorization](Authorization.md), [Account security](AccountSecurity.md), [Rate limiting](RateLimiting.md), [Cryptography](Cryptography.md), [Cache](Cache.md), [Events](Events.md), [Storage](Storage.md), [Queue](Queue.md), [Scheduler](Scheduler.md), [Redis](Redis.md), [outgoing HTTP](HttpClient.md), [Health](Health.md), [Diagnostics](Diagnostics.md), and [Testing](Testing.md). These are distinct v2 pages because their APIs exist in the current core; planned capabilities appear only as explicit limitations in their guides.

Do not mechanically rewrite `/docs/v1.x` with v2 snippets. Publish v2 under a separate version selector and route only after the v2 source and public examples have been reviewed against a reproducible release artifact. [Upgrade from v1.x](UpgradeFromV1.md) gives application migration steps.
