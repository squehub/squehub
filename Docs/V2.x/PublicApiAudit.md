# Phase 26A public API audit

This is the v2 development-tree API freeze inventory. Phase 26A is implemented and its focused Windows verification passed. The final Phase 26 Windows suite passed **2,955 tests, 22,755 assertions, 90 skips**, with zero failures, errors, or risky tests; native Linux and live-backend qualification remain open. The framework rule is **simple to use, powerful underneath**: application code imports deliberate gateways, while subsystem implementation classes keep their own ownership boundaries.

Public exceptions and interfaces live either as exact `App\Plugins` aliases in the [supported-symbol tables](Plugins.md#supported-symbols) or in their documented canonical subsystem namespaces. There is no catch-all `App\Plugins` autoload fallback. Canonical names remain usable; the gateway is the recommended compact application import surface.

The symbol-by-symbol classification found no Plugins file that should be reclassified as an accidentally exposed internal or v1-only compatibility symbol. The duplicate public surface was the six static Route verb methods, not an entire class alias.

## Findings and changes

1. **Duplicate route registration vocabulary.** `App\Plugins\Route` exposed six short static verb methods while the canonical v2 route contract was path-first. The first-party use was one integration test, and two guides promoted the shortcuts. The six methods were removed, the test now exercises path-first names/groups/middleware, and the guides give an explicit migration expression. This changes an unreleased development API, not the v1 `$router` bridge.
2. **Incomplete helper inventory.** `lock(): LockManager` existed and was documented in the Locks guide, but the complete Helpers inventory and `GlobalHelpersTest` omitted it. Both now include it. No helper behavior changed.
3. **Incomplete Plugins table.** Eight existing public symbols (`Health`, `HealthCheck`, `HealthManager`, `HealthReport`, `HealthResult`, `Mfa`, `Translation`, and `ViewContext`) appeared in guide prose but were absent from the supported-symbol tables. They are now classified there, and a symbol-loading test covers every `App/Plugins/*.php` file without freezing a private implementation list.
4. **MCP protocol comment.** A source comment implied that `mcp/sdk` 0.8.1 could not select the newer stateless era. It now states SqueHub's deliberate 2025-11-25 STDIO advertisement while acknowledging the SDK's 2026-07-28 support. The advertised revision and protocol behavior did not change.

Representative Windows contract checks passed: `PluginsGatewayTest` **7 tests/89 assertions**, `GlobalHelpersTest` **7/163**, and `PluginsSymbolsTest` **4/369**. The Plugins-symbol test loads every Plugins file; routing, CLI-help, configuration, HTTP/API, ORM, Package, and Kit suites remain part of the full regression gate. A broader public API filter passed **67 tests/1,076 assertions** before the added symbol test; the final full-suite gate covers it. No other public rename or removal is supported by the audit evidence. Future API additions should preserve the path-first route vocabulary and name their owner before adding a Plugins alias.
